\section{Overview}

The methodology combines (i)~classical automated preparation for tabular traffic events and (ii)~a production \emph{Flowmatic} platform with an adaptive \textbf{core processing unit} that routes heterogeneous sensor streams to modality-safe neural checkpoints. Figure~\ref{fig:batch-upload-pipeline} and Figure~\ref{fig:smart-city-streaming} summarise the two deployment modes evaluated in Chapter~\ref{chap:results}.

\section{Data Quality Assessment}

The assistant computes a weighted Data Quality Index (DQI):
\begin{equation}
\label{eq:dqi}
\mathrm{DQI} = \frac{\sum_{i=1}^{6} w_i Q_i}{\sum_{i=1}^{6} w_i}, \quad Q_i \in [0,1],
\end{equation}
over completeness, consistency, accuracy, timeliness, uniqueness, and validity. Completeness follows $C = 1 - |M|/|D|$; timeliness uses exponential decay $T = \exp(-\lambda \bar{a})$. In the deployed platform, analogous checks appear as schema typing, duplicate detection, and Z-score outlier flags (\texttt{QualityService}).

\section{Classical Preparation Pipeline}

Quality-guided preprocessing selects imputation and validation rules from the DQI profile. Automated feature engineering generates cyclical temporal encodings
\begin{equation}
f_{\sin}(t) = \sin(2\pi t/P), \quad f_{\cos}(t) = \cos(2\pi t/P),
\end{equation}
traffic intensity features, and spatial proxies. Ensemble anomaly scoring combines Isolation Forest, LOF, and One-Class SVM:
\begin{equation}
A(x) = \sum_{k=1}^{3} \beta_k s_k(x).
\end{equation}
Downstream tabular classifiers (XGBoost, Random Forest) are evaluated with cross-validation in the classical study (Section~\ref{sec:classical_results}).

\section{Adaptive Core Unit and Model Registry}

\subsection{Registry}

Each production checkpoint $m$ exposes metadata: kind (e.g.\ \texttt{patchtst\_forecast}), dataset affinity, tasks, sensor kinds, optional geo requirement, and priority. The registry loads from local \texttt{metadata.json} files and Hugging Face manifest entries.

\subsection{Routing policy}

For sensor kind $k$ and payload features $\mathbf{f}$, the router builds an event profile (modality, preferred task, geo flag). In \textbf{Manual} mode the operator selects model $m^{*}$. In \textbf{Auto} mode:
\begin{equation}
m^{*} = \arg\min_{m \in \mathcal{M}_k} \pi(m \mid \mathbf{f}),
\end{equation}
where $\mathcal{M}_k$ filters incompatible modalities/tasks and $\pi$ is a priority score (lower is better). Anomaly-capable tasks receive precedence when anomaly detection is enabled. Optional LLM refinement applies only when saving Auto policy bindings---not on every event---to bound latency.

\begin{algorithm}[H]
\caption{Rule-based model routing (Auto mode)}
\begin{algorithmic}[1]
\State \textbf{Input:} sensor kind $k$, payload $\mathbf{f}$, registry $\mathcal{M}$, anomaly flag $a$
\State $\mathit{profile} \gets \textsc{Classify}(k, \mathbf{f})$
\If{$a$ \textbf{and} $\exists m \in \mathcal{M}$ with task anomaly matching $\mathit{profile}$}
  \State \Return best-priority anomaly model
\EndIf
\State $\mathcal{C} \gets \{ m \in \mathcal{M} : \mathit{modality}(m)=\mathit{profile.modality} \land \mathit{task}(m)\supseteq \mathit{profile.task}\}$
\State \Return $\arg\min_{m\in\mathcal{C}} \mathit{priority}(m)$
\end{algorithmic}
\end{algorithm}

\section{Insight Engine and Copilot}

The Insight Engine composes deterministic analytics (hotspots, drift, correlation) with optional LLM narration constrained to retrieved pipeline context. This replaces SHAP-on-trees for \emph{platform} explainability while neural models retain reconstruction-based diagnostics (TranAD, SAITS).

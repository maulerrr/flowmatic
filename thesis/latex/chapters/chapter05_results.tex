\chapter{Results and Discussion}

\section{Overview}
\label{sec:exp_overview}

This chapter answers the research questions in Section~\ref{sec:research_questions} through three evaluation layers:
\begin{enumerate}
  \item \textbf{Platform validation (RQ2)} --- reproducible API experiments on the deployed Flowmatic stack (batch upload and live smart-city workbench).
  \item \textbf{Neural portfolio evaluation (RQ3)} --- eight modality-specific Hugging Face checkpoints on held-out temporal test splits with multi-seed replication ($s\in\{42,7,2026\}$), sequence ablations, cross-dataset transfer, and streaming inference latency.
  \item \textbf{Routing implementation (RQ4)} --- Manual/Auto registry behaviour in the workbench (quantitative router ablations deferred).
\end{enumerate}

An \textbf{archival classical pilot} (offline Python, June 2025 memoir) informs \textbf{RQ1} but is not re-executed in this repository; Section~\ref{sec:classical_results} cites it with explicit scope boundaries.

Neural results are reproduced with \texttt{python models/paper/run\_phase3\_core.py}. Checkpoints are published on Hugging Face under \texttt{@pushthetempo/flowmatic-*}.

\subsection{Hold-out validation}

Neural models never observe the test partition during training. Windows are extracted in temporal order: earliest 70\% train, next 15\% validate, final 15\% test (Table~\ref{tab:split_protocol}). Reported RMSE, masked MSE, and macro-F1 are computed only on the test split.

\subsection{Multi-seed robustness}

Each architecture is trained independently for seeds 42, 7, and 2026 with fixed hyper-parameters (\texttt{phase3\_multiseed\_suite.yaml}). We report mean, standard deviation, and 95\% confidence interval $\bar{m} \pm 1.96\, s/\sqrt{n}$ across seeds ($n=3$).

\section{Archival Classical Preparation Pilot}
\label{sec:classical_results}

The June 2025 memoir reported an offline Python experiment: automated preparation versus raw data, simple preprocessing, and generic FeatureTools-style automation, with XGBoost as the downstream classifier. On Astana tabular features it reported \textbf{0.9683 accuracy} and \textbf{0.9676 F1-score}, versus raw data (0.7823 accuracy) and generic AutoML features (0.9234); an IF/LOF/OCSVM ensemble reached F1 = 0.858 for anomalies.

\textbf{Scope boundary.} These numbers are \emph{not} stored in Hugging Face, \emph{not} served by the NestJS upload API, and \emph{not} reproduced by any script in the current repository (\texttt{thesis/GAP\_ANALYSIS.md}). They remain motivational evidence for preparation strategy design. \textbf{RQ1} is therefore answered in two parts: (a)~archival tabular gains in the pilot; (b)~operational preparation via platform QC and cleaning (Section~\ref{sec:platform_cases}).

\section{Neural Production Portfolio}
\label{sec:neural_portfolio}

\subsection{Model definitions}

Eight checkpoints form the official portfolio: PatchTST and iTransformer (traffic forecast), TranAD (anomaly), TimesBlock (weather), STGCN (graph traffic), SAITS (imputation), Transformer classifier (severity), and DLinear (energy). Mathematical definitions appear in Section~\ref{sec:neural_formulations}.

\subsection{Multi-seed test performance}

Table~\ref{tab:multiseed_aggregate} lists held-out test metrics aggregated across seeds. Main observations:
\begin{itemize}
  \item \textbf{Severity classification:} macro-F1 = $0.911 \pm 0.017$ (three-seed mean on the test split; not comparable to the archival XGBoost pilot, which used a different feature pipeline and CV protocol).
  \item \textbf{Anomaly reconstruction:} TranAD test RMSE = $0.035 \pm 0.004$ on normalised windows (reconstruction objective, not horizon forecasting).
  \item \textbf{Weather forecasting:} TimesBlock RMSE = $0.034 \pm 0.002$ on the HF weather bundle.
  \item \textbf{Graph traffic:} STGCN RMSE = $0.479 \pm 0.002$ on 32-node subgraphs of HF traffic.
  \item \textbf{Speed forecasting (iTransformer):} RMSE $\approx 0.999 \pm 0.001$ indicates a failed slot under the current eight-epoch budget; the checkpoint remains in the registry for routing demos but should not be treated as production-ready forecasting evidence.
\end{itemize}

Figure~\ref{fig:neural-multiseed} shows seed dispersion; Figure~\ref{fig:neural-forecast-rmse} ranks forecasting RMSE across checkpoint families. These held-out test metrics provide initial multi-task evidence for \textbf{RQ3}; external SOTA comparison on METR-LA/PEMS remains future work.

\section{Ablations and Generalisation}
\label{sec:ablations}

\subsection{Sequence length}

Table~\ref{tab:seq_ablation} and Figure~\ref{fig:seq-ablation} compare window lengths $L\in\{24,96\}$. Longer context helps DLinear on ETT (0.147 vs 0.241 RMSE) but hurts PatchTST on Astana density (0.807 vs 0.559). Production models use $L=48$ as a balanced default.

\subsection{Cross-dataset transfer}

Table~\ref{tab:cross_transfer} and Figure~\ref{fig:cross-transfer} report training on one HF bundle and testing on another without fine-tuning. Transfer RMSE remains finite but degrades relative to in-domain runs, indicating domain shift between energy and weather telemetry.

\subsection{Streaming inference latency}

Figures~\ref{fig:streaming-latency} and~\ref{fig:streaming-throughput} benchmark TorchScript exports on GPU with batch sizes $\{1,16,64\}$. Mean single-event latency stays below 2\,ms for compact models (DLinear, TimesBlock) and below 2\,s for large Transformers.

\section{Discussion}
\label{sec:discussion}

\textbf{Evidence tracks.} Platform metrics (Table~\ref{tab:upload-pipeline-experiment}) and neural metrics (Table~\ref{tab:multiseed_aggregate}) are reproducible from repository scripts. Archival classical numbers are cited for methodology continuity only.

\textbf{Test-set discipline.} Neural metrics use the held-out 15\% temporal test split. Platform upload metrics validate engineering latency and are complementary.

\textbf{External validity.} METR-LA and PEMS-BAY are ingested but not yet used as hold-out targets for Astana-trained models. Cross-dataset transfer within HF bundles provides a first generalisation check.

\textbf{Explainability.} Classical SHAP attributions applied only to the offline pilot. Production uses LLM-generated pipeline summaries and Insight Engine narratives without formal calibration; neural models expose reconstruction residuals (TranAD) and imputation masks (SAITS) as diagnostics.

\textbf{Routing evidence.} Manual/Auto routing is \textbf{implemented} and demonstrated in the workbench (\textbf{RQ4}). Formal router-vs-oracle ablations, CRPS scores, and AUROC for anomaly events are not yet reported and are listed as future work.

\section{Summary}

The experimental record supports four conclusions aligned with the research questions: (1)~archival preparation improved tabular classification in the June 2025 pilot, while the platform operationalises QC and cleaning as a measured service; (2)~Flowmatic batch upload latency and quality scoring are reproducible on Docker Compose; (3)~the eight-model neural portfolio provides multi-dataset, multi-seed evidence on held-out test data with published Hugging Face artifacts; (4)~registry-based routing \textbf{implements} modality-aware inference in the smart-city pipeline, with quantitative routing evaluation left for future work.

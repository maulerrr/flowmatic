\section{Overview of the Evaluation Programme}
\label{sec:exp_overview}

This chapter reports three complementary evaluation layers that together answer the research questions posed in Chapter~\ref{chap:intro}:
\begin{enumerate}
  \item \textbf{Classical preparation study} (original dissertation protocol): multi-dimensional DQI, tabular feature engineering, ensemble anomaly detectors, and XGBoost/Random Forest classification on Astana and public traffic benchmarks.
  \item \textbf{Production platform validation}: reproducible API experiments on the deployed Flowmatic stack (batch upload and live smart-city workbench).
  \item \textbf{Neural production portfolio} (Phase~2--3): eight modality-specific checkpoints evaluated on held-out temporal test splits with multi-seed replication ($s\in\{42,7,2026\}$), sequence ablations, cross-dataset transfer, and streaming inference latency.
\end{enumerate}

All neural numbers are reproducible from the monorepo via \texttt{python models/paper/run\_phase3\_core.py}; checkpoints are published on Hugging Face under \texttt{@pushthetempo/flowmatic-*} to avoid Git LFS limits.

\subsection{Hold-out validation}

Neural models never observe the test partition during training. Windows are extracted in temporal order; the earliest 70\% train, next 15\% validate, and final 15\% test (Table~\ref{tab:split_protocol}). Reported RMSE, masked MSE, and macro-F1 are computed \emph{only} on the test split. This design prevents leakage from future timesteps while remaining compatible with streaming smart-city pipelines where recent history informs the next prediction.

\subsection{Multi-seed robustness}

Each production architecture is trained independently for seeds 42, 7, and 2026 with fixed hyper-parameters (\texttt{phase3\_multiseed\_suite.yaml}). We report the mean, standard deviation, and 95\% confidence interval $\bar{m} \pm 1.96\, s/\sqrt{n}$ across seeds ($n=3$).

\section{Classical Preparation Results (Historical Baseline)}
\label{sec:classical_results}

The original dissertation evaluated automated preparation against raw data, simple preprocessing, and generic FeatureTools-style automation using XGBoost as the downstream classifier. On Astana, the full preparation pipeline achieved \textbf{0.9683 accuracy} and \textbf{0.9676 F1-score}, outperforming raw data (0.7823 accuracy) and generic AutoML features (0.9234). The ensemble anomaly detector (Isolation Forest + LOF + One-Class SVM) reached F1 = 0.858, exceeding any single detector.

These classical results remain valid as \emph{preparation-strategy baselines}. They demonstrate that domain-aware quality indexing and feature generation improve tabular classification. The Flowmatic platform extends---rather than replaces---this evidence by operationalising preparation as a service and adding neural task specialists for forecasting, imputation, and reconstruction-based anomaly scoring.

\subsection{Multi-seed test performance}

Table~\ref{tab:multiseed_aggregate} lists held-out test metrics aggregated across seeds. Highlights:
\begin{itemize}
  \item \textbf{Severity classification:} macro-F1 = $0.911 \pm 0.017$, exceeding the classical XGBoost F1 ($0.968$ accuracy $\approx$ high but on a different feature pipeline).

\end{itemize}

\section{Ablations and Generalisation}
\label{sec:ablations}

\subsection{Sequence length}

Table~\ref{tab:seq_ablation} and Figure~\ref{fig:seq-ablation} compare window lengths $L\in\{24,96\}$. Longer context helps DLinear on ETT (0.147 vs 0.241 RMSE) but hurts PatchTST on Astana density (0.807 vs 0.559), suggesting modality-specific horizon tuning. Production models use $L=48$ as a balanced default.

\subsection{Cross-dataset transfer}

Table~\ref{tab:cross_transfer} and Figure~\ref{fig:cross-transfer} report training on one HF bundle and testing on another without fine-tuning. Transfer RMSE remains finite but degrades relative to in-domain runs, quantifying domain shift between energy and weather telemetry.

\subsection{Streaming inference latency}

Figure~\ref{fig:streaming-latency} and Figure~\ref{fig:streaming-throughput} benchmark TorchScript exports on GPU with batch sizes $\{1,16,64\}$. Mean single-event latency stays below 2\,ms for compact models (DLinear, TimesBlock) and below 2\,s for large Transformers---informing Auto routing latency budgets in production.

\section{Discussion}
\label{sec:discussion}

\textbf{Test-set discipline.} All neural metrics in Table~\ref{tab:multiseed_aggregate} come from the held-out 15\% temporal test split. Platform upload metrics reflect full-file processing and are complementary---they validate engineering latency, not generalisation.

\textbf{External validity.} METR-LA and PEMS-BAY are ingested and available for future Astana$\rightarrow$PeMS transfer experiments; the current portfolio evaluation emphasises in-domain test splits plus HF cross-transfer.

\textbf{Explainability shift.} Classical SHAP attributions on tree models are replaced in production by LLM-generated pipeline summaries and Insight Engine narratives (Chapter~\ref{chap:implementation}). Neural models expose reconstruction residuals (TranAD) and attention-based imputation masks (SAITS) as mechanistic diagnostics.

\textbf{Remaining gaps.} Auto-router vs oracle ablations, CRPS/probabilistic scores, and AUROC for anomaly events are scheduled future work (Chapter~\ref{chap:conclusion}).

\section{Summary}

The experimental record supports three claims: (1)~automated classical preparation improves tabular traffic classification; (2)~the Flowmatic platform implements this logic as a reproducible service with live smart-city validation; (3)~the eight-model neural portfolio delivers multi-dataset, multi-seed evidence on held-out test data with published artifacts suitable for Q1-style reproducibility.
